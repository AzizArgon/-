# Дорожная карта и промты для сессий

Файл для Азиза и для будущих сессий Claude.
Каждый блок «Промт» — первое сообщение новой переписки. Одна переписка = одна фаза.

## Общие правила для каждой сессии (Claude, читай это)
- В начале: прочитай `CLAUDE.md` и этот файл. В `docs/history.md` смотри только нужный раздел.
- Коммит и push после каждого законченного пункта, не в конце. Если лимит кончится, следующая сессия продолжит по `git log`.
- Тесты без живых запросов к ИИ. Живой ИИ — только для финальной проверки, экономно (бесплатные лимиты Gemini/Groq).
- Перед изменением схемы БД — резервная копия `database.db`.
- Проверка в браузере + скриншоты для всего, что видит пользователь.
- В конце: краткое объяснение простыми словами (для защиты), обновить Статус в `CLAUDE.md` (коротко!) и подробности в `docs/history.md`, отметить фазу в этом файле, коммит, push.
- `CLAUDE.md` держать до ~60 строк.
- Если идея не входит в текущую фазу — не делать, а записать в «Идеи на потом» внизу этого файла.

## Фаза 5.0 — Демо-магазины
**Промт:**
> Прочитай CLAUDE.md и docs/roadmap.md, выполни фазу 5.0.

**Задача:**
- `scripts/seed_demo.py`: одной командой создаёт 3 демо-магазина (вымышленные названия, разные районы Ташкента, телефоны, Telegram), один — проверенный.
- Товары — на основе прайса Age Computers: у каждого часть ассортимента (с пересечениями, чтобы популярные товары были у 2–4 магазинов), цены ±5–15%, разное наличие и свежесть, один магазин в UZS.
- В одном магазине 2–3 товара сильно ниже рынка — для флага «цена ниже рынка».
- Повторный запуск без дублей.
- Gshop (`samples/old_store_2023.xlsx`, цены 2023 года) сейчас не публиковать. Записать в docs/history.md особенности для фаз 6 и 7 (см. ниже).
- Проверка в браузере: карточка i5-12400F с несколькими магазинами, сортировка «рекомендованные» и «дешевле», флаг «ниже рынка».

## Фаза 5.1 — Фильтры по категориям
**Промт:**
> Прочитай CLAUDE.md и docs/roadmap.md, выполни фазу 5.1.

**Задача:**
- Словарь характеристик для каждой категории: фиксированные ключи, типы и допустимые значения/единицы (это ядро «стандартизации»). Минимум:
  - ОЗУ: тип (DDR3/4/5), форм-фактор (DIMM/SODIMM), объём, частота, комплект (1×/2×), ECC;
  - процессоры: бренд, линейка, сокет, ядра/потоки, встроенная графика, BOX/OEM;
  - видеокарты: чип, производитель чипа, объём памяти, тип памяти;
  - SSD: объём, интерфейс (NVMe/SATA), форм-фактор (M.2/2.5");
  - HDD: объём, форм-фактор, скорость;
  - материнские платы: сокет, чипсет, форм-фактор, тип памяти;
  - мониторы: диагональ, разрешение, частота, матрица;
  - блоки питания: мощность, сертификат 80 PLUS, модульность;
  - корпуса, охлаждение, периферия: 2–3 ключевых фильтра.
- Нормализатор: «16GB», «16 ГБ», «16Gb» → одно значение. Правила, парсер и ИИ пишут характеристики только по словарю.
- Пересчитать характеристики существующих товаров (резервная копия БД). Не выдумывать: нет в строке — нет значения (правило «предположений ИИ» сохраняется).
- API: доступные фильтры категории со счётчиками товаров у каждого значения.
- Каталог: при выборе категории появляются её фильтры, счётчики, фильтры в адресе страницы.
- Отчёт: какой % товаров каждой категории получил ключевые характеристики (цифра для диплома).

## Фаза 5.2 — Ручное добавление товаров
**Промт:**
> Прочитай CLAUDE.md и docs/roadmap.md, выполни фазу 5.2.

**Задача:**
- «Найти в каталоге»: поиск с автоподсказками по эталонным товарам → цена, валюта, состояние, наличие → предложение добавлено. Если товара нет — создать новую карточку через короткую форму (категория + название; характеристики по словарю 5.1).
- «Вставить текстом»: поле для текста (например, пост из Telegram, несколько строк «i5 12400f б/у 110$») → тот же конвейер, что для файлов (кэш → правила → ИИ → Anti-Fraud) → тот же предпросмотр и публикация.
- Оба способа — в кабинете продавца рядом с загрузкой файла.
- Ручное добавление не должно помечать остальные товары «нет в наличии» (это делает только полная загрузка прайса).

## Фаза 7 — Грязные прайсы и замер точности
**Промт:**
> Прочитай CLAUDE.md и docs/roadmap.md, выполни фазу 7.

**Задача:**
- Поддержка структуры Gshop: на листе несколько таблиц бок о бок («наименование | цена» ×3) → делить лист на вертикальные блоки, подзаголовки разделов отслеживать в каждом блоке отдельно.
- Строки вроде «Оплата только в национальной валюте» не определяют валюту — показывать продавцу как подсказку. Пометки «(только в сборках)» → поле «примечание», не в название.
- Сгенерировать 5–10 «грязных» версий прайса (сленг, опечатки, перепутанные столбцы, объединённые ячейки, CSV с «;», PDF) + эталонная разметка (правильные ответы).
- Замер с пустым кэшем: точность по полям (категория, бренд, модель, цена, состояние), доля флагов Anti-Fraud, время, число запросов. Gemini vs Groq на одних данных.
- Итог — таблица в `docs/experiment.md` (готовый материал для экспериментальной главы).
