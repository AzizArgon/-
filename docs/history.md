# История проекта pc_market

Подробности по фазам, технические решения и замеры. Краткие правила и дорожная карта — в `CLAUDE.md`.

## Стек
- Backend: Python 3.11+, FastAPI, Pydantic v2, Uvicorn, SQLAlchemy, SQLite (`database.db`). Alembic НЕ используем — `create_all`.
- Frontend: React (Vite) + Tailwind CSS + Axios + react-i18next (сейчас только `ru`; весной добавить `uz`, `en`). Все тексты интерфейса — через i18n, не хардкодить.
- AI: `markitdown` (Excel/PDF/CSV → Markdown) + `google-genai` (Gemini Flash; актуальную версию модели проверять при реализации). Большие прайсы отправлять частями (чанками). Ответ — строгий JSON.
- Auth: JWT + passlib/bcrypt.
- Секреты (GEMINI_API_KEY, JWT secret) — только в `.env`, `.env` в `.gitignore`.

## Схема БД (черновик)
- `users`: id, email, password_hash, role (buyer / seller / master / admin), created_at
- `stores`: id, user_id, name, inn_stir, phone, telegram, address, district, is_verified
- `categories`: id, name, mxik_code
- `products` (эталон): id, category_id, brand, model, normalized_name, specs_json
- `offers`: id, product_id, store_id, raw_name, price, is_in_stock, condition (new / used / refurbished), updated_at
- `price_history`: id, offer_id, price, recorded_at
- `fraud_flags`: id, offer_id, type, level, reason_key, params, source, status (active / disputed / dismissed)
- `masters` (после ноября): id, user_id, service_name, phone, address, services_list, rating

## Объём работ
**Ноябрь (MVP):** регистрация/вход, загрузка прайса drag-and-drop, ИИ-парсер с предпросмотром, каталог с поиском и фильтрами, карточка товара с предложениями магазинов и плашками Anti-Fraud, базовая аналитика цен.
**После ноября:** мастера, админка и модерация, оспаривание флагов, языки uz/en.
**Не делаем:** оплата/корзина (только «Связаться»), карты/геолокация (только район/адрес), внутренний чат (только телефон/Telegram), мобильная версия.

## Фаза 1 — готово (backend: каркас, БД, авторизация)
- Структура `backend/app/{api,core,db,schemas,services}`, точка входа `backend/main.py`, CORS для `http://localhost:5173`, `GET /api/health`.
- Модели SQLAlchemy (`app/db/models.py`): users, stores, categories, products, offers, price_history, fraud_flags. Таблицы создаются через `create_all` при старте сервера.
- Авторизация (`app/api/auth.py`): `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`. Проверка ролей — `require_role(...)` в `app/api/deps.py`.
- Проверено вручную: регистрация, вход, `/me`, дубликат email → 409, неверный пароль → 401, регистрация как admin → 422, без токена → 401.

## Принятые технические решения
- Python 3.12 в виртуальном окружении `backend/.venv` (системный Python 3.10 не трогаем).
- `bcrypt==4.0.1` закреплён: passlib несовместим с bcrypt ≥ 4.1. Пароль 8–72 символа (лимит bcrypt).
- JWT через PyJWT, срок жизни 24 ч, в токене `sub` = user id и `role`. Вход принимает JSON (`email`, `password`), токен передаётся как `Authorization: Bearer ...`.
- При регистрации можно выбрать только роль `buyer` или `seller`; `admin` назначается вручную, `master` — после ноября.
- Email приводится к нижнему регистру.
- Enum-поля хранятся в БД как строки (`native_enum=False`). В SQLite включены внешние ключи (`PRAGMA foreign_keys=ON`).
- Путь к БД — `backend/database.db` (абсолютный, не зависит от папки запуска). `.env` лежит в `backend/`.
- Таблица `masters` пока не создана (после ноября). Магазин (`stores`) при регистрации продавца не создаётся — будет отдельным шагом.

## Фаза 3 — готово (магазин, импорт прайса, ИИ-парсер, курс ЦБ)
- Реальный прайс для тестов: `F:\claudy\samples\Price of Age Computers (9).xlsx` (вне репозитория, в git не кладём).
- Конвейер (`app/services/`): `importer.py` (файл → markitdown → очистка → Gemini частями → `price_imports.rows_json` → публикация), `price_cleaner.py` (очистка кодом), `ai_parser.py` (промпт, схема ответа, ограничитель частоты), `exchange.py` (курс cbu.uz).
- Очистка кодом: пропуск листа `Export` (дубликат), удаление NaN/`Unnamed: N`/пустых строк, строки-подзаголовки («DDR», «Блоки питания», шапки таблиц) → раздел для строк ниже, обрезка столбца «характеристики» до 120 символов и любой ячейки до 200. На реальном прайсе: 4685 строк Markdown → 2440 строк товаров, ~10 частей по 250 строк.
- ИИ возвращает: категорию (slug из справочника), бренд, модель, нормализованное название, цену, состояние (new/used/refurbished), 2–6 характеристик. Без цены → «нет в наличии» (решает код, не ИИ). Противоречия в строке ИИ не исправляет (для Anti-Fraud).
- Gemini: модель `gemini-3.5-flash`, thinking `low`. `gemini-3.8-flash` в октябре 2026 отвечал 50–150 с на запрос — слишком медленно. Бесплатный тариф: 5 запросов/мин → ограничитель `gemini_rpm`, повтор при 429 (ждём сколько просит API) и 503 (перегрузка). **Суточный лимит бесплатного тарифа — 20 запросов на модель** (один прайс ≈ 10 запросов). Поэтому при исчерпании квоты парсер сразу переключается на запасные модели (`gemini_fallback_models`: 3.5-flash-lite, 3.1-flash-lite); если кончились все — импорт `failed` с ошибкой `ai_quota`. Всё настраивается в `.env` (`GEMINI_MODEL`, `GEMINI_RPM`, `PARSER_CHUNK_ROWS`).
- Проверено 25.10.2026: реальный прайс — 6 из 10 частей разобраны (остальные упали по суточной квоте до появления переключения моделей), 1492 товара опубликованы за 2,7 с; мини-CSV в UZS со сленгом («проц i5 12400f б/у» → Intel Core i5-12400F, Б/у) прошёл весь путь через интерфейс.
- Импорт идёт в фоне; фронт опрашивает `GET /api/imports/{id}` каждые 2 с и показывает прогресс. После перезапуска сервера незавершённые импорты помечаются `failed` (`interrupted`). Важно: `--reload` при правке кода ждёт окончания фонового импорта.
- Публикация: товар сводится в карточку по `products.match_key` = категория + название в нижнем регистре без знаков. Предложение магазина ищется по `raw_name` (исходная строка без цены), так повторная загрузка обновляет цену. Позиции магазина, которых нет в новом файле, → «нет в наличии». История цен пишется при новой цене или смене валюты.
- Категории: 23 штуки с кодами МХИК в `app/db/seed.py` (коды найдены вручную на tasnif.soliq.uz; для HDD, корпусов и охлаждения взяты ближайшие общие коды). Справочник заполняется при старте сервера.
- API: `GET/PUT /api/stores/me`, `POST /api/imports` (файл + `currency`), `GET /api/imports`, `GET /api/imports/{id}`, `POST /api/imports/{id}/publish`, `GET /api/categories`, `GET /api/rates/usd`.
- Frontend: `/seller` (данные магазина, drag-and-drop, история загрузок), `/seller/imports/:id` (прогресс, редактируемая таблица: поиск, фильтр «требуют внимания» — без цены/без бренда/категория «Прочее», 50 строк на страницу, удаление строк, публикация).
- Тесты: `cd backend` → `.\.venv\Scripts\python.exe -m pytest`. Кейс Anti-Fraud «KingBank DDR5 / KJXS DDR4» — `tests/fixtures/antifraud_cases.json` (кейсы Anti-Fraud — см. «Фаза 4»).
- Схема БД изменилась (`categories.slug`, `products.match_key`, `offers.currency`, `price_history.currency`, новые `price_imports`, `exchange_rates`). Alembic нет → при изменении схемы удалить `backend/database.db` (тестовые аккаунты пропадут).

## Фаза 3.1 — готово (оптимизация парсера под бесплатные лимиты)
**Решение Азиза: платный тариф не подключаем, работаем на бесплатных лимитах.** Пункты про Gemini выше частично устарели — актуально это:
- Порядок разбора строки: **кэш → правила → ИИ**. В ИИ уходит только то, что не нашлось в кэше и не разобрано правилами.
- **Код, а не ИИ** берёт из таблицы цену, артикул и наличие (`price_cleaner.py`: роли столбцов по шапке — цена/наименование/артикул/характеристики/наличие; без шапки — последнее число в строке; `parse_price` понимает «1 250 000», «35,», «$120»). Цена берётся только из столбца с заголовком «цена/опт/…»: цену в безымянном столбце (у HP-принтеров в реальном прайсе) код не берёт — сознательно строже, чем ИИ. В ИИ отправляется только `id|название | доп. текст`, без цен и характеристик.
- **Правила без ИИ** (`rule_parser.py`): аккуратные строки процессоров Intel/AMD, памяти, SSD, HDD, материнских плат, видеокарт, мониторов. Строки с «б/у», «восстановленный», «уценка» всегда идут в ИИ. Противоречия (DDR5/DDR4, «GTX 3050») правила не исправляют — для Anti-Fraud.
- **Кэш** (`parse_cache`): ключ — нормализованное название (`cache_key`: нижний регистр, без знаков). Пишутся ответы ИИ (`ai`), правки продавца при публикации (`seller`, перезаписывают ИИ) и не-товары (`{"skip": true}`, чтобы заметки не уходили в ИИ повторно).
- **Ответ ИИ — компактный JSON** с короткими ключами `i,c,b,m,n,s,p`; thinking `minimal` (у Gemini 3.x полностью не выключается). Части по 400 строк: 800 не уместились в ответ flash-lite. При обрыве ответа (`MAX_TOKENS`) часть сама делится пополам.
- **Запасной провайдер — Groq** (`openai/gpt-oss-120b`, бесплатно: 30 запросов/мин, 1000 запросов/сутки, но только 8K токенов/мин → части по 60 строк, ограничитель по токенам). Включается, когда у всех моделей Gemini кончилась квота или они не отвечают. Ключ `GROQ_API_KEY` в `.env` (бесплатно на console.groq.com/keys). Ключ добавлен 25.10.2026, Groq проверен вживую (см. «Фаза 3.3»). Сравнение на 25.10.2026: OpenRouter — 50 бесплатных запросов/сутки; Mistral — условия бесплатного тарифа неясны (нужно согласие на обучение на данных).
- Упавшие строки больше не теряются: они остаются в предпросмотре с пометкой «не распознано» (цена из файла уже есть), кнопка «Повторить распознавание» (`POST /api/imports/{id}/retry`) отправляет в ИИ только их. В таблице у строки видно, откуда она: правило / кэш / ИИ.
- Статистика каждого импорта — `price_imports.stats_json` (строк, правилами, из кэша, в ИИ, запросов, делений, секунд) и строкой над таблицей. Колонка добавлена в локальную БД через `ALTER TABLE` (данные сохранены).
- Замер: `scripts/benchmark_parser.py <файл> [--tokens] [--live]` (`--live` — реальный прогон с пустым кэшем, рабочий кэш не трогает). Фикстура ответа ИИ для тестов: `scripts/record_ai_fixture.py` → `tests/fixtures/ai_answer.json`. Тесты (30 шт.) не делают живых запросов.
- ⚠ `--reload` перезапускает сервер при изменении любого `.py` в `backend/` (включая `scripts/`, `tests/`) — во время импорта код не править.

**Замер на реальном прайсе (2438 строк товаров), 25.10.2026:**

| | До (фаза 3) | После, без кэша | Дозапуск с кэшем | Повторная загрузка |

## Фаза 3.2 — готово (проверка цен и характеристик)
- **Строки без цены (проверено по исходному файлу):** из 515 строк у 507 цены в файле действительно нет. Код пропускал 3 цены, исправлено:
  - если столбцов цен несколько («Цена опт» / «Цена розница»), берётся первый заполненный, «опт» в приоритете (Redragon, Sharkoon);
  - товар записан в файле дважды (Jonsbo HF2-120B: с ценой и без) → строка без цены больше не обнуляет цену при публикации; из дублей с ценой остаётся первый (ASUS ROG STRIX B850-A: 320 и 370 → 320).
  - Сознательно НЕ берутся как цена: штрихкоды (13 цифр, Gigabyte), число в соседнем столбце при пустом столбце цены (PowerCase, 2 строки), число в столбце без заголовка (принтер HP 2602sdw). Такие строки подсвечены в предпросмотре — продавец впишет цену сам.
- **Характеристики от ИИ проверяются по тексту строки** (`ai_parser.spec_in_text` / `split_specs`): каждое число и слово значения должно быть в строке (единицы и порядок слов не важны: «4GB DDR4» = «DDR4 4GB», «1.5m» = «1,5м»; англ. → рус. по небольшому словарю: wireless = беспроводн…; окончания русских слов не важны). Не найдено → `specs_guess` — «предположение ИИ»: показывается в предпросмотре курсивом, **не сохраняется в `products.specs_json` и не используется Anti-Fraud**. В кэше хранятся все характеристики и перепроверяются при каждом разборе.
  - На реальном прайсе: 4970 характеристик подтверждены, 937 (16%) — предположения (например, «Windows 11», «Full-Tower», сокет у «проц i5 12400f», «LGA2011-3» у Xeon).
  - Уже сохранённые в БД товары очищены разово: 885 предположений удалены, 2987 подтверждённых оставлены.
  - Правила тоже не додумывают: память без пометки SODIMM больше не получает «form_factor: DIMM».
- Тесты: 42 шт., без живых запросов к ИИ.

## Фаза 4 — готово (Anti-Fraud)
- `app/services/antifraud.py`: `check_offer(row, market_usd, usd_rate)` → список флагов `{type, level, reason, source}`. **Сначала правила кодом, ИИ — вторым слоем**: подсказка ИИ добавляется, только если правила этот тип не нашли, и всегда с уровнем `info`.
- Правила смотрят только на то, что написал продавец: исходная строка, артикул и **подтверждённые** характеристики. «Предположения ИИ» (`specs_guess`) и название от ИИ в проверках не участвуют.
- Типы и уровни:
  - `spec_mismatch` (warning): разные поколения DDR в одной строке (GDDR/LPDDR не считаются, «DDR4/DDR5» — тоже); несуществующие GTX 20xx/30xx и RTX 10xx/16xx.
  - `server_hardware` (warning; у ноутбуков/системных блоков — info): Xeon, китайские платы X99/X79 (Huananzhi, Machinist, Jingsha…) или X99 без известного бренда, память ECC/REG, серверные сокеты LGA2011/2066/3647 (только у процессоров и плат — у кулеров список сокетов норма).
  - `mining` (warning): «майнинг», P104/P106, CMP; серверные БП/БП для майнинга. Б/у RX 470/570/580/5700 — info.
  - `used_as_new` (danger): «б/у», «восстановленный», «уценка», «витринный» в строке, но состояние «новый».
  - `fake_capacity`: флешка/карта памяти ≥ 1 ТБ — danger; SSD дешевле $25 за ТБ — warning.
  - `noname_psu`: «noname» — warning; ≥ 500 Вт дешевле $20 — warning; бренд не указан — info.
  - `price_below_market`: цена в USD < 60% медианы других магазинов (нужно ≥ 2 предложения) — warning, < 40% — danger.
- Формулировки мягкие («возможно», «уточните у продавца»), ИИ называет только тип. Причина хранится как **ключ перевода + параметры** (`fraud_flags.reason_key`, `params`, например `ddr_mismatch` + `{gens: "DDR4, DDR5"}`), тексты — во фронте: `flags.reason.<key>` в `ru.json` (для uz/en весной достаточно добавить переводы). Подсказки ИИ — ключи `ai_<тип>`. Тест проверяет, что у каждого ключа из `antifraud.py` есть текст в `ru.json`.
- ИИ: в ответ парсера добавлен ключ `f` — коды подозрений (только если явно видны в строке); отдельных запросов к ИИ для Anti-Fraud нет, токенов почти не прибавилось. Хранится в строке как `ai_risks` и в кэше разбора (`risks`). Строки, разобранные правилами, ИИ не видит — для них работают только правила.
- Где работает: флаги считаются, когда предпросмотр готов (`price_imports.rows_json[].flags`, `stats.flagged`), пересчитываются после правки строки продавцом (`POST /api/imports/{id}/check`, без ИИ, через 0,6 с после правки) и при публикации пишутся в `fraud_flags`. При повторной загрузке активные флаги заменяются; оспоренные/отклонённые типы повторно не поднимаются.
- Фронт: плашки под названием в предпросмотре (ℹ сведения / ⚠ внимание / ⛔ важно, пометка «по мнению ИИ»), фильтр «Только с подозрениями», флаги warning/danger попадают в «Требуют внимания».
- `scripts/recheck_flags.py` — разово прогнать правила по всем предложениям и импортам в БД (после изменения правил).
- Проверено 25.10.2026: на реальном прайсе (2430 строк) — 8 флагов, все настоящие (KingBank DDR5/DDR4; GTX 2060 Super и GTX 3050 у OCPC/Peladin/Arktek), ложных нет (найдены и исправлены: артикул «AG4731TB» читался как объём 4731 ТБ, кулеры со списком сокетов LGA2011, «восстановление напряжения» у сетевого фильтра). «Грязный» CSV через Gemini (1 запрос, 3,6 с): X99 + Xeon, флешка 2TB, noname БП, P106 после майнинга, KingBank, ECC REG — помечены правилами, ИИ назвал те же риски; честно помеченная б/у GTX 1660 без флага, после смены состояния на «Новый» в предпросмотре сразу появился флаг «Возможно, б/у».

## Фаза 5.2.1 — готово (посты-карточки из Telegram, понятные ошибки, 25.10.2026)
- **Причина сбоя** (импорт №13, реальный пост Азиза): разбор считал любой пост списком «строка = товар». Цена «950.000 сум» читалась как 950 (точка — как дробная часть), строка «Цена: …» прицеплялась к предыдущей строке «Чипы: SK Hynix…» — получилось 2 «товара» из строк про чипы, ИИ правильно счёл их не товарами, итог пустой → общая ошибка `empty_file` («Не удалось распознать прайс»).
- **Тип поста** (`text_import.is_card_post`): «карточка одного товара» = 2+ строк «Ключ: значение» и одна цена (двуязычный пост повторяет ту же цену); иначе — «список». Карточка (`card_row`): название — первая строка, не «ключ: значение»; строки «ключ: значение» — характеристики; всё это — исходный текст строки (`raw_name`), поэтому нормализатор и проверка «правило честности» читают характеристики из того, что написал продавец (чипы, тайминги — не в словаре, отбрасываются). Цену и валюту берёт код; состояние из «Состояние/Holati» тоже берёт код (`CleanRow.condition` побеждает ответ ИИ).
- **Двуязычные посты**: если есть строки с русскими ключами, строки с латинскими (узбекскими) ключами считаются копией и не идут в товар — один товар, а не два. Узбекские слова переводятся кодом (`uz_to_ru`): B/U → б/у, Narxi → цена, so’m → сум (все виды апострофа), to’plam → комплект, Holati → состояние, yangi → новый и др.
- **Цены в сумах**: «950.000», «1.250.000», «950 000», «1,250,000» с «сум/so’m» — точка/запятая/пробел как разделитель тысяч (у сумов нет дробей); «1.2 млн» по-прежнему 1 200 000.
- **Мусор**: флаги и эмодзи убираются; строки с доставкой, «Купить / Sotib olish», «Buyurtma», @username, телефонами — не товары; заголовок рекламного блока («Доставка:») скрывает и пункты под ним («• По Фергане — Такси») до пустой строки.

## Фаза 6 — готово (мониторинг цен и аналитика, 25.10.2026)

### Методика расчёта (для реферата)
- **Все расчёты — в долларах США.** Цены в сумах переводятся по курсу ЦБ Узбекистана **на дату этой цены**, а не на сегодня: иначе изменение курса выглядело бы как изменение цены товара. Исторические курсы берутся из архива cbu.uz (`/json/USD/ГГГГ-ММ-ДД/`) и хранятся в таблице `exchange_rates`; курс на дату = последний установленный не позже этой даты. Покупателю цены показываются в сумах (основная валюта), пересчитанные — с «≈».
- **Рыночная цена товара = медиана** цен предложений в наличии от разных магазинов (у магазина одно предложение на карточку). Медиана, а не среднее: одна аномальная цена (ошибка или демпинг) её почти не сдвигает. Пример: 92, 100, 112 → рынок 100.
- **Новые, б/у и восстановленные считаются отдельно** — у каждого состояния свой рынок.
- **Метка предложения** — отклонение от рыночной цены в процентах: в пределах ±3% — «по рынку», иначе «ниже рынка на 8%» / «выше рынка на 12%».
- **Цена в прошлом** (для графика): на каждый из последних 90 дней берётся последняя известная цена каждого магазина из истории цен, затем медиана. Учитываются предложения, которые сейчас в наличии.
- **Изменение цены товара** («за 3 месяца цена выросла на 5%») считается **по одним и тем же магазинам** в начале и в конце периода: магазин, который появился позже (например, с более высокой ценой), не создаёт ложного «роста».
- **Индекс категории** — как изменились цены **одних и тех же товаров**: для каждого товара отношение «цена сейчас / цена в начале периода» (товар сравнивается сам с собой), затем среднее геометрическое этих отношений (индекс Джевонса — так считают элементарные индексы цен статистические службы). Средняя цена всей категории не используется: появление дорогих новых моделей подняло бы её без всякого подорожания. Геометрическое среднее симметрично: +25% у одного товара и −20% у другого дают 0%. Периоды — неделя, месяц, 3 месяца; начало периода = 100.
- **По малым данным выводов нет**: меньше 2 магазинов → «недостаточно данных» вместо рыночной цены и меток; история короче 2 недель → нет фразы об изменении; меньше 3 товаров в категории → индекс не показывается.
- Реализация: `services/market.py` (расчёт в памяти ~0,3 с на 3,5 тыс. предложений, кэш до изменения предложений или истории); API — блок `market` в карточке товара, `/api/market/overview`, `/api/seller/analytics`. Тесты — `tests/test_market.py`.

### Правила для постов (пункт 2 задания)
- Копия из Telegram: заголовки «[дата] Имя:» делят текст на отдельные посты; «Переслано из …», «[ 3 фото ]» — служебные строки.
- Две цены = один товар: «120У.Е. 115У.Е.» → новая цена, «Цена 15$ / Подписчикам 13$» и «Опт / Розница» → обычная/розничная цена; вторая цена — примечание продавца (`offers.note`, новая колонка, `ALTER TABLE`; в предпросмотре и карточке товара).
- Цена без валюты: ≥ 10 000 → сумы, меньше → доллары, всегда с подсветкой «проверьте валюту» (раньше — валюта по умолчанию из формы; параметр больше не нужен). «Цена 140.000» читается по слову «Цена». «y.e» латиницей = у.е.
- Состояние — только по явным словам: б/у, бу, used, ishlatilgan → б/у; новый, в плёнке, запечатан, yangi, muhrlangan → новый; openbox, вскрыт → **«новый, вскрытая упаковка»** (`new_openbox`); иначе **«не указано»** (`unknown`) + подсказка «Состояние не указано — выберите», строка в «требуют внимания». «Как новый», «обслужена», «Holati zor» ничего не значат. Только для постов: прайс-файл магазина по-прежнему «новый» по умолчанию. Anti-Fraud: openbox считается новым («б/у как новый»), «не указано» — ни новым, ни б/у.
- Фильтр «Состояние» в каталоге (`?condition=`), пять значений.
- Строки сравнения («Пизже i5-12400f», «лучше чем», vs) не попадают в товар; узбекская кириллица (Нархи, Ҳолати, янги, сотилади); T-Force → TeamGroup (серия), Axle — бренд; «3 tb Hitachi» → категория HDD (подсказка, если ИИ не уверен).

### Исправления по результатам замера (общие правила)

Определяющие характеристики берутся из строки продавца, даже если ИИ выкинул их из названия: тип памяти платы, OEM/BOX, DDR у ОЗУ, частота монитора (Redmi G27Q 240 и 320 Гц — разные модели). - **Бренды**: опечатка = ровно одна правка известного бренда от 5 букв (SAPPHRIE, ASSUS, Lexsar, Gigabyet); «Apacer» ≠ Acer, «Vissonic» ≠ ViewSonic (так ошибалась первая версия с порогом похожести — найдено пересчётом базы). Видеокарта без бренда производителя: NVIDIA/AMD — производитель чипа, а не бренд.
- **Нормализатор**: «1440Hz» больше не читается как 440 Гц; «Кулер … заводская термопаста» — кулер, «Термопаста … для кулера» — паста, «Кулер … CORELIQUID» — жидкостное.
- **ИИ**: промпт — товар без подходящей категории (коврик, кронштейн, роутер) не пропускать, а ставить «Прочее» (flash-lite пропускал 15 из 70 позиций Gshop); ответ терпим к форме (Groq присылал характеристики объектом — вся часть из 60 строк падала после 5 попыток).

- Порт 443 занят VPN (Xray), Cloudflare ходит к серверу по HTTP :80 (зона в режиме Flexible). Сделано: :80 для pcmarket + :2053 с сертификатом Let's Encrypt (webroot через :80, продление certbot). Для «Full (strict)» владельцу домена — два правила Cloudflare только для поддомена (Origin Rule → порт 2053, Configuration Rule → SSL Full (strict)); режим зоны не меняли.
- Доступ: SSH-ключ `id_ed25519_pcmarket` (без пароля — для `deploy.bat`), пароль sudo вводил Азиз в терминале один раз (`deploy/server_setup.sh`). Без пароля админу разрешено только действовать от `pcmarket` и перезапускать/смотреть службу. Firewall на сервере выключен — не включали (риск закрыть порты чужих сервисов); backend слушает только 127.0.0.1:8020.
- backend — systemd `pcmarket.service` (Restart=always, MemoryMax=700M, ProtectSystem=strict). Проверено: штатный перезапуск — 4 с; `kill -9` — поднялся сам за 2 с.
- Frontend собирается на ноутбуке (на сервере нет Node.js и мало памяти), настройки публичной сборки — `frontend/.env.public` (`/api`, плашка). SQLite оставлен: для демо достаточно.
