# Материалы для защиты

Рабочее название — `pc_market`. Здесь всё, что нужно, чтобы объяснить проект комиссии простыми словами: что это, как устроено, какие цифры получены и что ответить на вопросы.

## 1. Что за проект и какую проблему решает

В Узбекистане компьютерную технику продают сотни небольших магазинов, и каждый ведёт прайс по-своему: Excel с объединёнными ячейками, PDF, посты в Telegram со сленгом («проц», «видюха», «озу 16гб»). Один и тот же процессор в десяти прайсах записан десятью способами, поэтому покупатель не может просто сравнить цены, а рынок никто не видит целиком.

Система принимает прайс в любом виде, сама приводит каждую строку к стандарту — эталонная карточка товара с кодом МХИК и характеристиками — и собирает предложения всех магазинов на одной странице (как Oson Apteka для лекарств). Поверх этого работают проверка подозрительных предложений (Anti-Fraud) и мониторинг цен: рыночная цена, история, индексы по категориям.

## 3. Что делает каждая часть

| Часть | Что делает |
|---|---|
| **Загрузка** | Продавец перетаскивает файл (Excel, CSV, PDF) или вставляет пост из Telegram. Есть и третий путь — найти товар в каталоге и указать цену. |
| **markitdown / pdfplumber** | Превращают любой файл в таблицу в виде текста (Markdown). Так весь дальнейший разбор работает одинаково для любого формата. |
| **Очистка** | Код находит в строке цену, валюту, артикул и наличие, отслеживает разделы прайса, убирает рекламу и телефоны. Эти поля никогда не доверяются ИИ: ошибка в цене недопустима. |
| **Кэш** | Каждая разобранная строка запоминается. Повторная загрузка того же прайса проходит за секунды и без единого запроса к ИИ. |
| **Правила** | Регулярные выражения разбирают аккуратные строки (процессоры, память, SSD, видеокарты и др.). Что разобрали правила, в ИИ не отправляется. |
| **ИИ (Gemini, запасной Groq)** | Разбирает только оставшиеся «грязные» строки: определяет категорию, бренд, модель и характеристики. Отвечает строгим JSON; если у Gemini кончилась квота, автоматически подключается Groq. |
| **Нормализатор и словарь** | Словарь задаёт для каждой из 23 категорий набор характеристик и их единицы. Нормализатор приводит написания к одному виду: «16гб», «16 GB», «16G» → 16 ГБ. |
| **Проверка правдоподобия** | Характеристика от ИИ сохраняется, только если её значение есть в строке продавца и попадает в разумный диапазон. Всё, что ИИ «додумал», отбрасывается. |
| **Anti-Fraud** | Сначала правила кодом (серверный Xeon, DDR4 вместе с DDR5, флешка на 2 ТБ, «б/у» в новом, цена сильно ниже рынка), затем ИИ — только подсказкой уровня «к сведению». Формулировки мягкие («уточните у продавца»), продавец сможет оспорить флаг. |
| **Предпросмотр** | Продавец видит, как система поняла каждую строку, с плашками подозрений, и может всё поправить перед публикацией. Его правки запоминаются в кэше. |
| **База данных** | SQLite: эталонные карточки, предложения магазинов, история цен, флаги, курсы ЦБ. Одно предложение магазина на карточку, история цен пишется при каждом изменении. |
| **Каталог и мониторинг** | Покупатель ищет товар, фильтрует по характеристикам и видит предложения всех магазинов в сумах. Мониторинг считает медиану рынка, метки «ниже/выше рынка», график цены и индексы категорий. |

## 4. Три уровня достоверности данных

| Уровень | Что это | Пример | Сохраняется? |
|---|---|---|---|
| **Указано продавцом** | Значение прямо есть в строке прайса | «DDR5 16GB 5600» → тип DDR5, 16 ГБ, 5600 МГц | Да |
| **Выведено правилом** | Однозначно следует из написанного, вывод делает код | «i5-12400**F**» → встроенной графики нет | Да, со звёздочкой «выведено правилом» |
| **Предположение ИИ** | ИИ «знает», но продавец этого не писал | «проц i5 12400f» → сокет LGA1700 от ИИ | **Нет** — показывается в предпросмотре серым и не сохраняется |

Почему так: покупатель должен видеть только то, за что отвечает продавец или однозначная логика. Ошибка ИИ в характеристике — это обман покупателя, даже если ИИ прав в 95% случаев.

## 6. Технологии и почему выбраны

| Технология | Почему |
|---|---|
| **FastAPI (Python)** | Быстрый современный веб-фреймворк, сам строит документацию API (Swagger), а на Python удобнее всего работать с таблицами и ИИ. |
| **React (Vite) + Tailwind** | Самый распространённый способ делать интерактивные страницы; Vite запускается мгновенно, Tailwind позволяет оформлять без отдельных CSS-файлов. |
| **SQLite** | База в одном файле, не нужен отдельный сервер — для диплома и локального запуска этого достаточно; переход на PostgreSQL почти не меняет код (SQLAlchemy). |
| **Gemini + Groq** | Gemini даёт лучшую точность и бесплатный лимит; Groq — другой провайдер с другой моделью, тоже бесплатный, страхует, когда квота Gemini кончилась. |
| **markitdown** | Библиотека Microsoft, которая превращает Excel, CSV и PDF в Markdown — один вход для всего разбора вместо отдельного кода под каждый формат. |
| **react-i18next** | Все тексты интерфейса в одном файле перевода: узбекский и английский добавляются без правки кода. |

## 7. Ограничения и перспективы

- **Цена на картинке поста.** Многие магазины публикуют прайс фотографией — сейчас такие посты не разбираются. Перспектива: распознавание текста (OCR) перед тем же разбором.
- **Холодный старт.** Сервис полезен, когда в нём много магазинов, а магазины придут, когда есть покупатели. Перспектива: автосбор постов из публичных Telegram-каналов магазинов (с их согласия), чтобы каталог был наполнен с первого дня.
- **Фото товаров.** Пока у карточек нет фото. План: одно фото на эталонную карточку, удаление фона, выбор человеком из 4–6 вариантов.
- **Мобильная версия.** Сейчас только компьютер; большинство покупателей в Узбекистане — со смартфона, поэтому мобильная вёрстка — важный следующий шаг.
- **Языки.** Интерфейс на русском; узбекский и английский подготовлены (все тексты — ключи перевода).
- **Модерация.** Нет админки: проверка магазинов по СТИР, рассмотрение оспоренных флагов Anti-Fraud — в плане.
- **Размещение.** Работает на ноутбуке; размещение на VPS — отдельная фаза.

## 8. Вероятные вопросы комиссии

1. **Откуда берутся коды МХИК?** — Из справочника категорий, который заполнен вручную по классификатору tasnif.soliq.uz. ИИ только выбирает категорию из списка, а код подставляет программа — ИИ код не придумывает.

2. **Что если ИИ ошибётся?** — Цену, валюту, артикул и наличие ИИ не трогает — их берёт код. Характеристики ИИ сохраняются, только если есть в строке продавца. А всё остальное продавец видит в предпросмотре и правит до публикации.

3. **Почему медиана, а не среднее?** — Одна ошибочная или мошенническая цена (например, $1 вместо $100) сильно сдвигает среднее, а на медиану почти не влияет. Для рынка с небольшим числом магазинов это важно.

4. **Зачем два провайдера ИИ?** — На бесплатном тарифе у каждого есть суточный лимит. Если у Gemini квота закончилась, разбор не останавливается, а автоматически переходит на Groq. Заодно это позволило сравнить модели в эксперименте.

5. **Чем отличается от Uzum / OLX?** — Uzum — маркетплейс: продаёт сам и требует от магазина карточки в своём формате. OLX — доска объявлений без стандартизации: один товар — сотни разных объявлений. У нас один товар — одна карточка со всеми магазинами, а прайс можно загрузить как есть.

6. **Как привлечь продавцов?** — Продавцу ничего не нужно переделывать: загрузил свой Excel или переслал пост — товары в каталоге. Плюс бесплатная аналитика: где его цены выше или ниже рынка и каких популярных товаров у него нет.

7. **Что с персональными данными?** — Покупатели не регистрируются и данных не оставляют. О магазине хранится только публичная информация (название, телефон, адрес). Пароли — только в виде хэша bcrypt, телефоны и ники из постов при разборе отбрасываются.

8. **Сколько стоит работа ИИ?** — Сейчас 0: всё работает в бесплатных лимитах. Полный прайс на 2 438 строк без кэша — около 5 запросов и 71 тыс. входных токенов; повторная загрузка — 0 запросов. На платном тарифе это центы за прайс.

9. **Как проверяли точность?** — Собрали набор с правильными ответами: 7 специально испорченных файлов (сленг, опечатки, объединённые ячейки, CSV, PDF), реальный прайс 2022 года, размеченный вручную, и Telegram-посты. Скрипт сравнивает ответ системы с разметкой по каждому полю. Подробно — в экспериментальной главе.

10. **Почему не обучили свою модель?** — Для обучения нужны десятки тысяч размеченных строк и вычислительные мощности. Готовая языковая модель с хорошим промптом, правилами и проверкой дала 97–100% точности без обучения.

11. **Что такое эталонная карточка?** — Одна запись о товаре (например, Intel Core i5-12400F) с брендом, моделью, характеристиками и кодом МХИК. Все строки разных магазинов про этот товар привязываются к ней как предложения.

12. **Как система понимает, что две строки — один и тот же товар?** — Из строки строится ключ: категория, бренд, код модели и определяющие характеристики (например, объём памяти у видеокарты). Совпали ключи — один товар. Точность сведения — 95,8%.

13. **Что делает Anti-Fraud и не обидит ли он честного продавца?** — Он ищет типичные уловки: серверный Xeon под видом игрового процессора, «флешку на 2 ТБ» за $9, б/у под видом нового, цену вдвое ниже рынка. Формулировки мягкие («возможно, уточните у продавца»), на чистых строках ложных флагов не было, а продавец сможет оспорить флаг.

14. **Почему правила раньше ИИ?** — Правила работают мгновенно, бесплатно и предсказуемо, их легко проверить. ИИ нужен только там, где правила не справились, — так экономятся лимиты и время.

15. **Как работает с валютами?** — Продавец указывает валюту прайса (доллары или сумы), цена хранится как есть. Покупателю показываются сумы по курсу ЦБ (cbu.uz, раз в день) с пометкой «≈», ведь оплата в Узбекистане — только в национальной валюте. Аналитика считается в долларах по курсу на дату цены.

16. **Откуда история цен, если система новая?** — История пишется при каждом изменении цены. Для старых периодов загружен архивный прайс магазина за декабрь 2022 года, а для показа добавлена демо-история, явно помеченная «включает демо-данные».

17. **Что будет, если загрузить прайс повторно?** — Цены обновятся, история пополнится, а товары, которых больше нет в файле, станут «нет в наличии». Разбор берётся из кэша — за секунды и без ИИ.

18. **Почему SQLite, а не PostgreSQL?** — Для локального запуска и диплома не нужен отдельный сервер базы. Код написан через SQLAlchemy, так что переход на PostgreSQL при размещении — это смена строки подключения.

19. **Масштабируется ли система?** — Разбор идёт частями и параллельно, расчёт рынка на 3,5 тыс. предложений занимает ~0,3 с. Для тысяч магазинов нужны PostgreSQL, очередь задач и платный тариф ИИ — архитектура это позволяет.

20. **Что если магазин специально завысит или занизит цену?** — Метки «ниже/выше рынка» и флаг «цена сильно ниже рынка» показывают это покупателю. Рыночная цена — медиана, поэтому один магазин её не сдвинет.

21. **Как обрабатываются посты из Telegram?** — Пост очищается от рекламы, телефонов и хэштегов, разбивается на товары (одна цена — один товар), понимаются русский и узбекский (латиница и кириллица). Если в посте нет модели, продавец видит понятное сообщение.

22. **Чем ваша работа научно отличается от простого вызова ChatGPT?** — ИИ — лишь один слой: до него код, кэш и правила, после — нормализация, проверка правдоподобия и Anti-Fraud. Именно эти слои подняли точность сведения карточек с 71,6% до 95,8% и убрали ложные флаги.

23. **Как защищены аккаунты продавцов?** — Пароли хранятся только как хэш bcrypt, вход по токену JWT, ключи ИИ и секреты — в файле `.env`, который не попадает в репозиторий. Продавец видит и меняет только свои прайсы.

24. **Почему нет корзины и оплаты?** — Сервис — справочник цен, а не магазин: покупатель находит лучшее предложение и связывается с магазином по телефону или Telegram. Это проще для магазинов и не требует лицензий на приём платежей.

25. **Что дальше?** — Фото товаров, мобильная версия, узбекский и английский языки, админка с модерацией флагов, автосбор постов из каналов и размещение в интернете.
