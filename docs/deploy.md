# Публичная версия: https://pcmarket.khudoberdi.uz

Демо-версия дипломного проекта на арендованном сервере (VPS), чтобы куратор и знакомые открывали сайт по ссылке без ноутбука автора.
На этом же сервере работают сайты другого человека — их не трогаем: у нашего сайта свои пользователь, папки, служба и файл nginx.
Адрес сервера, пароли и ключи в репозитории не хранятся: они лежат на ПК автора вне git (`F:\claudy\server_passwords.txt`, `F:\claudy\server_notes.txt`).

## Как это устроено

```
Посетитель ──HTTPS──> Cloudflare ──> nginx на сервере ──> /            → собранный frontend (статичные файлы)
                                                      └─> /api/...     → backend (FastAPI), только 127.0.0.1:8020
```

- **Cloudflare** — «прокладка» перед сервером: даёт HTTPS-замок в браузере, прячет адрес сервера и передаёт настоящий IP посетителя в заголовке `CF-Connecting-IP`.
- **nginx** — веб-сервер, который уже стоял на сервере. Для нашего сайта — отдельный файл `pcmarket`: порт 80 (сейчас Cloudflare ходит к серверу так) и порт 2053 с сертификатом Let's Encrypt (для режима Cloudflare «Full (strict)», см. ниже). Порт 443 на сервере занят другой программой — не используем.
- **backend** — служба systemd `pcmarket`: сама запускается после перезагрузки сервера и перезапускается при падении (проверено: после «убийства» процесса поднялась через 2 с). Ограничена 700 МБ памяти и своей папкой.
- **База** — тот же SQLite-файл `database.db`, что и на ноутбуке. Для демо с десятками посетителей его хватает; переход на PostgreSQL — смена одной строки подключения, если понадобится.

## Что где лежит на сервере

| Что | Где | Кто может читать |
|---|---|---|
| Код (git-клон репозитория) | `/opt/pcmarket/app` | только пользователь сайта `pcmarket` |
| База | `/opt/pcmarket/app/backend/database.db` (в git не попадает) | только `pcmarket` |
| Настройки и ключи (`.env`) | папка `backend` в коде, права `600` | только `pcmarket` |
| Прайсы и кэш для демо | `/opt/pcmarket/private` | только `pcmarket`, по ссылке не открываются |
| Резервные копии базы | `/opt/pcmarket/backups` | только `pcmarket` |
| Собранный frontend | `/var/www/pcmarket` | nginx (это публичные файлы сайта) |
| Конфиг nginx | `/etc/nginx/sites-available/pcmarket` + `/etc/nginx/snippets/pcmarket-app.conf` | шаблоны — `deploy/nginx/` |
| Службы | `pcmarket.service`, `pcmarket-backup.timer` | шаблоны — `deploy/systemd/` |

Вход на сервер — только по SSH-ключу (`~/.ssh/id_ed25519_pcmarket`, короткое имя `pcmarket` в `~/.ssh/config`).
Администратору разрешено без пароля только: действовать от имени `pcmarket`, перезапускать и смотреть нашу службу (`/etc/sudoers.d/pcmarket`).
Первичная установка — `deploy/server_setup.sh` (один раз, с паролем sudo); повторный запуск безопасен.

## Как обновить сайт

1. Внести правки на ноутбуке, закоммитить (Claude делает это сам).
2. Запустить **`deploy.bat`** в корне проекта. Он сам:
   push на GitHub → копия базы сервера → `git pull` на сервере → зависимости Python → сборка frontend на ноутбуке и загрузка на сервер → перезапуск backend → передача курса ЦБ → проверка, что сайт и API отвечают.
3. В конце должно быть `DEPLOY OK`. База на сервере при обновлении не заменяется.

Frontend собирается на ноутбуке, а не на сервере: на сервере мало свободной памяти и нет Node.js. Настройки публичной сборки — `frontend/.env.public` (плашка «Демо-версия», адрес API `/api`).

**Курс ЦБ.** Сайт cbu.uz отвечает только узбекским адресам, а сервер за рубежом. Поэтому сервер сам курс не запрашивает (`CBU_FETCH=false`), а `deploy.bat` берёт курс на ноутбуке и передаёт на сервер. Курс обновляется при каждом deploy; между ними сайт показывает последний известный курс с его датой.

## Защита публичной версии

- **Регистрация продавцов — только по коду-приглашению** (`SELLER_INVITE_CODE` в `.env` сервера, код — в `server_passwords.txt`). Покупатели регистрируются свободно. На ноутбуке код не нужен.
- **Дневные лимиты** (чтобы посторонние не потратили бесплатную квоту ИИ): 10 загрузок прайса на магазин, 40 на весь сервер, 100 запросов к ИИ на сервер. При превышении — понятное сообщение «попробуйте завтра»; строки, на которые не хватило ИИ, можно распознать позже кнопкой «Повторить».
- **Вход:** не более 10 неудачных попыток с одного IP за 15 минут; регистраций — не более 5 в час с одного IP.
- **Настоящий IP посетителя** nginx берёт из заголовка Cloudflare (доверяет ему только от адресов Cloudflare) и передаёт backend в `X-Real-IP`; backend доверяет этому заголовку только от nginx на этой же машине.
- **Плашка** «Демо-версия дипломного проекта…» на всех страницах, в подвале — ссылка на GitHub.
- **Поисковики:** `noindex` в заголовке ответа и в `<meta>` на каждой странице + `robots.txt`. (Cloudflare на всём домене подставляет свой robots.txt с «Allow»; запрет индексации всё равно действует через `noindex`.)
- **Пароли** демо-аккаунтов на сервере заменены случайными (старые есть в публичном репозитории). Новые — в `F:\claudy\server_passwords.txt`. Если пересобрать демо-базу на сервере, пароли снова станут старыми — после этого обязательно запустить `scripts/set_passwords.py` (см. `server_notes.txt`).
- Лимиты включаются только переменными в `.env` сервера; на ноутбуке всё работает как раньше.

## Логи

```bash
ssh pcmarket sudo journalctl -u pcmarket --no-pager -n 200
```
Состояние службы: `ssh pcmarket sudo systemctl status pcmarket --no-pager`. Перезапуск: `ssh pcmarket sudo systemctl restart pcmarket`.
Запросы к сайту в nginx — `/var/log/nginx/pcmarket.log`.

## Резервные копии

- Автоматически раз в день (около 03:30 по времени сервера, UTC) — `pcmarket-backup.timer`, хранятся последние 14 (`*_daily.db.gz`).
- Перед каждым `deploy.bat` — ещё одна копия, хранятся последние 5 (`*_before_deploy.db.gz`).
- Копия делается командой SQLite `.backup` — безопасно, пока сайт работает.
- **Скачать свежую копию на ноутбук:** `get_backup.bat` → файл появится в `F:\claudy\backups\server\`.
- Сделать копию прямо сейчас: `ssh pcmarket sudo systemctl start pcmarket-backup`.

### Как восстановить базу из копии

1. Выбрать копию: `ssh pcmarket "cd /tmp && sudo -u pcmarket ls -lt /opt/pcmarket/backups"`.
2. Восстановить (пример для копии `2026-10-26_0330_daily.db.gz`):
   ```bash
   ssh pcmarket "cd /tmp && sudo -u pcmarket bash -c 'cd /opt/pcmarket/app/backend && cp database.db database.db.broken && gunzip -c /opt/pcmarket/backups/2026-10-26_0330_daily.db.gz > database.db'"
   ```
3. Перезапустить backend: `ssh pcmarket sudo systemctl restart pcmarket` и открыть сайт.

## Если сайт не открывается

1. **Проверить, что отвечает:** `curl -I https://pcmarket.khudoberdi.uz/api/health`.
   - `502 Bad Gateway` от nginx — упал backend: смотреть логи (выше), потом перезапуск.
   - Ошибка Cloudflare `521/522` — не отвечает сам сервер или nginx: сообщить владельцу сервера.
   - Ошибка Cloudflare `525/526` — проблема с сертификатом на порту 2053 (только в режиме Full (strict)): `ssh pcmarket sudo certbot certificates` (сертификат `pcmarket`, продлевается сам).
2. **Backend не стартует после обновления** — в логах будет ошибка Python. Откатить код: на ноутбуке `git revert` последнего коммита и снова `deploy.bat`.
3. **Сайт открывается, но «Сервер недоступен»** — frontend не может достучаться до `/api`: проверить, что backend жив (п. 1), и что сборка была через `deploy.bat` (в ней адрес API — `/api`).
4. **Загрузка прайса пишет про лимит** — это защита демо-версии, сбросится завтра; лимиты меняются в `.env` сервера (затем перезапуск backend).
5. Перезагрузку **всего сервера** без согласования с владельцем не делать: на нём работают другие сайты.

## Cloudflare и HTTPS

Сейчас Cloudflare ходит к серверу по обычному HTTP на порт 80 (режим зоны Flexible) — посетитель всё равно видит HTTPS с замком.
Для режима **Full (strict)** (шифрование и между Cloudflare и сервером) всё готово на сервере (порт 2053, сертификат Let's Encrypt). Владельцу домена нужно добавить два правила — **только для поддомена**, режим всего домена не меняется:
1. *Rules → Origin Rules*: если Hostname равно `pcmarket.khudoberdi.uz` → Destination Port: `2053`.
2. *Rules → Configuration Rules*: если Hostname равно `pcmarket.khudoberdi.uz` → SSL: `Full (strict)`.
